# Challenge 8: Every new AI coding session knows where the client project stands

**Host:** a company that builds AI products for its clients

## In 60 seconds

The host builds AI products for its clients with coding agents (AI tools that write code). After the first deliverables, new ones keep arriving from client feedback, QA (quality assurance) testing and questions only the client can answer, spread across emails, meetings and documents. Coding agents lose that context between chats. Teams design a way for any agent to pick up a project knowing what is done, open and verified.

## The problem

> "Deliverables that haven't been implemented, open concerns from the client, and what's been verified or not gets lost"

Context lives in Markdown (plain-text) files in GitHub, and one person remembers which file holds what. Each new chat starts with virtually no context.

## Who it affects

- The person building each client product with coding agents
- The QA team
- Account managers
- The company's clients, who get asked for information

## How it works today

1. Client input arrives by email, meetings, WhatsApp, calls and in-platform feedback. AI note takers write up meetings.
2. A person passes it to a coding agent and asks it to update the context documents.
3. Each new chat, the person points the agent at the right documents. **Stalls:** the agent forgets, misses things from emails, or makes things up.
4. The agent's questions go back to the client by email, and the loop repeats over days or weeks.

## The challenge

How might we make sure any coding agent, in any new session, knows which deliverables are **done, open or verified** and **what the client has already answered**, so that the company reaches an invoice-ready product sooner and asks its clients less often?

## What good looks like

- "iterate faster"
- "reduce the number of times we ask our clients for additional information"
- "keeping track of all the things our clients wanted"
- "work on multiple issues at the same time"

## Scope for the weekend

| | |
|---|---|
| **In** | The company's sample project run through the team's system, showing what is done, open and in progress, the open client concerns, and the questions to ask the client. A wireframe, mockup or small demo on the team's own repository and test database is enough. |
| **Out** | The company's real repositories, databases, email and client projects. Going live. |
| **Stretch** | The same project picked up by a second coding agent. |

## Data

A sample project prepared by the company, with no real client details. The company holds an expected outcome for judging. Only the files in your challenge folder, made-up records and public sources go into any tool.

## Show this on Sunday

1. **A fresh session, days later:** the new chat "would know exactly like okay, these are the items that are still remaining."
2. **New feedback arrives:** a client email and a meeting write-up bring new feedback. Each new deliverable is captured, nothing in the email is missed, and finished items stay finished.
3. **A question only the client can answer:** logged with the other open questions, asked once, and the item updated when the answer comes back.
